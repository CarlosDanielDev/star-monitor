# Story — Analysis: pattern report across the corpus

Label: `story`

Parent: #{{EP}}

Measure what the 30 top READMEs share: section headers and their frequency, badges, table of contents, screenshots/images, code blocks, install / quick-start phrasing, license / contributing / community sections, document length. Output `analysis/report.md` — the numbers every playbook claim must cite.

Evidence: corpus from {{L1}} (manifest at `corpus/manifest.json:1`, 30 repos). Analysis reads only `corpus/` — no network — via `scripts/analyze_corpus.py` (target path, symbol `analyze_corpus`), so every number in the report is reproducible.

## Done when

- [ ] `python3 scripts/analyze_corpus.py` writes `analysis/report.md` with a header-frequency table (header → count out of 30) — `grep -c '^|' analysis/report.md` prints 20 or more — owner: implementer
- [ ] coverage stated — `grep -c '30/30' analysis/report.md` prints 1 or more — owner: implementer
- [ ] top-10 patterns each carry an `examples:` line naming 2+ corpus repos — `grep -cE '^examples:' analysis/report.md` prints 10 or more — owner: reviewer
- [ ] numbers reproducible — `python3 scripts/analyze_corpus.py --check` exits 0 (re-run matches committed report) — owner: implementer
- [ ] `npx --yes markdownlint-cli2` passes — owner: reviewer

## ADR stub

Parse headers with a plain regex over the raw markdown (` ^#{1,3} `) instead of a markdown AST library: the corpus is read-only evidence, header lines are unambiguous, and stdlib keeps the script dependency-free. Normalization: lowercase, strip emoji/punctuation, so `## 🚀 Getting Started` and `## Getting started` count as one pattern.

## Out of scope

- Content-quality judgments (which README is "better") — that is {{L3}}'s job, on top of these numbers.
- Re-fetching anything from the network.
